# Goal: goal assistance in the Jev plugin

Deliver a packaged, tested workflow in `plugins/jev-review` that helps users turn rough direction into an achievable next step, preserves clear requests, and asks focused questions when a material user choice is still open. The feature stays off/observe by default as specified below and does not gain authority to start native goal mode or implementation.

Completion requires direct evidence for all of these conditions:

1. **Behavior:** Prompt intent, relation to current work, and goal status route to answer, discuss, investigate, proceed, confirm-candidate, or ask-missing-information as appropriate. Tests cover the behavior cases in `behavior.md`, including detailed prompts, exploration, missing facts/preferences, mixed requests, short answers, corrections, status, cancellation, conflicts, and unsupported scope. Codex drafts prose; judge signals remain separate, evidence-grounded inputs to deterministic policy.
2. **Provider boundary:** A general MCP evaluation accepts bounded state and typed Choice, Score, and Noul questions without a fake file wrapper. A replaceable injected judge preserves native answers and provenance. Existing `jev_review`, `jev_signal`, TypeSafe, and OpenRouter contracts continue to work.
3. **State and safety:** Goal state is versioned and scoped to session plus workspace, survives clarification/resume, rejects stale revisions, and is idempotent for duplicate hook events. Unavailable or invalid judgment never becomes a pass. Inference and confidence never authorize implementation or `/goal`.
4. **Activation and integration:** A bundled UserPromptSubmit command hook and dedicated skill entrypoint support `off`, `observe`, and explicit `assist`; `observe` is the initial default. The hook is bounded, uses a fixed trusted output envelope, and falls back to concise guidance when the judge is unavailable. The workflow can also be entered manually. Package and MCP tests prove installation assets and old interfaces remain present.
5. **Privacy and documentation:** Setup, tuning, remote prompt-text handling, diagnostics, content opt-in/deletion, and state behavior are documented. Attachments, full transcripts, and repository files are not sent automatically; diagnostic content recording is opt-in. No silent preference learning is introduced.
6. **Evidence:** Deterministic failure/state tests pass, and the report compares normal Codex, the same workflow without an external judge, and that workflow with Jev on at least 30 development and 30 held-out synthetic/paraphrased cases. Held-out labels stay hidden until revisions freeze. The report records disagreements, latency, usage/cost, deviations, and limitations; actual user satisfaction remains unknown without user feedback. Stay within 300 remote requests and $5, and record a wall-clock stop cap before the run. If credentials or model access are unavailable, deliver the runnable harness and mark live results unverified. Report installed-Windows host acceptance separately; missing host evidence must never be described as full integration verification.

The final integrated candidate must pass `bun run validate` and `bun scripts/check-work-context.ts`. Use the Work Ledger MCP tools in `docs/agent/work/README.md` for worker context and receipts. Beads is the only live owner of issue status, dependencies, claims, blockers, and writable-path ownership; do not add YAML or another live checklist.
